# Stage 86: mandatory Risk & Veto for the selected synthetic F&O book

This stage extends the existing Stage55 SQLite execution book. The legacy default book is preserved. A newly configured **selected synthetic F&O book** pins a typed research/contract/policy/key boundary into its persistent account scope. Reopening that same database without the boundary, with a different key or with changed policy fails closed. Existing funded books are not silently migrated.

Every selected-account OPEN and FILL, including raw direct APIs and Stage77 delegation, passes through the same `_record` transaction boundary. `BEGIN IMMEDIATE` covers replay verification, persistent kill-switch precedence, exact head/risk revision matching, HMAC verification, fresh synthetic-data/expiry/lot/tick/debit checks, a recomputed Stage76 Risk & Veto review, and the cash/hold journal update. A faulty signer cannot bypass the transaction's own policy checks. Missing, stale, future, cross-ledger or mismatched evidence grants no hold or fill. Repeated operation IDs remain rejected without a second allocation.

The signed permit binds the full operation, complete configured research packet contents, local ledger scope, journal revision/tip, risk revision, telemetry and a short validity interval. The verification key is never written to SQLite or the reports. An evidence row commits atomically with each OPEN/FILL. Replay verifies coverage, canonical serialization, operation binding and signatures at their historic issuance time, so old valid fills remain inspectable after permit expiry. Missing proofs, changed signatures and missing persistent boundary markers fail closed.

CANCEL is a deny-only release operation and remains usable while killed or data is stale; it cannot increase a position. The existing unauthenticated Stage82 rearm API is denied for selected accounts. No automatic rearm route is added. Stop activation remains deny-only. New selected books require the same configuration/key on restart; otherwise they cannot resume or reconstruct trading authority.

The execution inventory names public order/approval/fill/cancel/reservation candidates across the package, including module-level research functions. The selected Stage55 entrypoints are enforced here. VirtualAccount, PaperIntentGateway, Stage19/49/53 books, pure execution simulators and CryptoVirtualAccount retain separate boundaries. They cannot write this selected ledger through its public API without the boundary; they are **not globally disabled or migrated**. Stage77's healthy caller telemetry is explicitly tested to fail on a selected account when it supplies no mandatory permit.

## Security scope and remaining work

The HMAC issuer is a privileged local **synthetic test control plane**, not authenticated human identity, an independent deployed risk process or an exchange-data attestation. The symmetric verifier key is available in the same Python process; hostile code with memory access or arbitrary filesystem write access is outside this local API boundary. Clock injection is a trusted replay/test facility; production wall-clock, signer custody, authenticated administration, revocation and process isolation remain unresolved. No live broker or network path is added; EVOLVE receives neither a signing key nor permission-mutation API.

Signed configuration still begins with fabricated research data. It cannot turn those inputs into genuine NSE evidence. Permissions/receipts retain no live or real-paper authority. This stage does not yet provide the restart-safe public F&O lifecycle adapter or enforce all committed-position budget sublimits; Stage87 addresses those in this same selected book. Cross-ledger capital authority and real F&O shadow readiness remain unresolved.

Validation evidence is recorded on the draft PR after the full regression and exact-commit three-version CI complete. Tests cover raw bypass, old-gateway bypass, missing/malformed/mismatched permits, a valid MAC with risk-veto telemetry or invalid contract economics, stale book/risk/data/permit evidence, kill precedence, restart downgrade attempts, duplicates, cross-ledger scope, deny-only cancellation and journal corruption.

Final local validation: **2,349 passed, 0 failed**, 30 new tests; 5 subtests are separate. Python 3.12.14, compilation and the whole-package import/dependency audit passed. GitHub CI is checked on the published commit before Stage87; no remote result is assumed in this file.
